3.1 Framework Overview
1. Client (React + Vite): pages, components, routing, state/context, API client (axios), Socket client, styling (Tailwind).
2. Server (Express/Node): routes → controllers → services → models; middleware (auth, error, validation, logger).
3. DB (MongoDB): collections: users, tasks, bids, bookings, payments, reviews, messages.
4. Services: Socket.io gateway (chat, notifications), Stripe Connect (escrow).
5. Infra: Git/GitHub, .env, Docker (optional), Vercel (client) + Render/Railway (server) + MongoDB Atlas.

3.2 Repo layout:
```
/frontend   → React app
/backend  → Express API
```


3.3 Component breakdown

3.3.1 Frontend (React + Vite) — runs in browser.
Function:
  - UI, user actions, form input, display data.
Interactivity:
  - Sends HTTP requests (axios) to backend.
  - Opens WebSocket (Socket.io) for chat/notifications.
  - Stores state (context/zustand).
  - Routes pages (react-router).
Endpoints it calls:
  - POST /auth/login
  - GET  /tasks
  - POST /bids
  - (etc.)
Rule:
  - Never talks to DB directly.

3.3.2 BACKEND (Express/Node) - runs on server
Function:
  - Business logic, auth, validation, DB access.
Interactivity:
  - Receives HTTP from frontend
  - Passes through middleware (auth, validation)
  - Controller -> Service -> Model -> DB
  - Sends JSON back
  - Emits Socket events

Layers:
  Routes:
    - Map URL -> controller.
    - Example: router.post('/tasks', createTask)
Controllers:
    - Handle request/response, call services.
Services:
    - Business logic.
    - Example: accept bid -> create booking -> trigger payment.
  Models:
    - Mongoose schemas; talk to MongoDB.

  Middleware:
    - auth (JWT), error handler, logger, validation.

Endpoints (examples):
  Auth:
    - POST /auth/register
    - POST /auth/login
  Tasks:
    - GET  /tasks
    - POST /tasks
    - PATCH /tasks/:id
  Bids:
    - POST  /tasks/:id/bids
    - PATCH /bids/:id/accept
  Bookings:
    - GET   /bookings
    - PATCH /bookings/:id/complete
  Payments:
    - POST /payments/intent
    - POST /payments/webhook
  Reviews:
    - POST /reviews
    - GET  /users/:id/reviews
  Chat:
    - GET /messages/:bookingId

3.3.3 DATABASE (MongoDB) - separate service
Interactivity:
  - Backend models query it (find, insert, update).
  - Frontend never touches it.
Collections:
  - users
  - tasks
  - bids
  - bookings
  - payments
  - reviews
  - messages

3.3.4 SERVICES (external / realtime)
Socket.io:
  - Bidirectional realtime.
  - Backend emits -> frontend listens.
  - Used for chat + live bid/booking notifications.
Stripe Connect:
  - Handles money.
  - Backend calls Stripe API.
  - Stripe sends webhooks back to backend to confirm payment.

3.3.5 INFRA
Git / GitHub:
  - Version control, portfolio.
.env:
  - Secrets (DB URI, JWT secret, Stripe keys).
Vercel:
  - Hosts frontend.
Render / Railway:

MongoDB Atlas:

3.4 TECH INTROS
React        : JS library for building UIs from reusable components. Runs in browser.
Vite         : Fast build tool/dev server for React. Replaces slow Create-React-App.
Node.js      : Runs JavaScript outside the browser - on your server.
Express      : Minimal Node framework for building HTTP APIs (routes, middleware).
MongoDB      : NoSQL database. Stores JSON-like documents, not tables.
Mongoose     : ODM library. Defines schemas + queries MongoDB from Node.
Socket.io    : Realtime bidirectional communication (WebSocket wrapper).
Stripe Connect: Payment platform; handles escrow, payouts, compliance.
JWT          : JSON Web Token - signed token for auth.
axios        : HTTP client for frontend to call backend.
Tailwind     : Utility-first CSS framework.










4.1 Workflow Sequence (people interacting)
1. Client registers → profile.
2. Client posts task (date, location, budget).
3. Cleaners browse → submit bids.
4. Client accepts bid → booking created.
5. Client pays → funds held in escrow.
6. Chat opens for coordination.
7. Cleaner completes → client confirms.
8. Escrow releases funds.
9. Both rate each other.
10. Reviews update profiles.



4.2 Workflow Sequence – Technical Components
1. React client → POST /auth/register → Express route → auth controller → bcrypt hash → User model → MongoDB.
2. Client → POST /tasks (JWT) → auth middleware → task controller → Task model → MongoDB.
3. Cleaner client → POST /tasks/:id/bids → bid controller → Bid model → MongoDB.
4. Client → PATCH /bids/:id/accept → bid service → creates Booking → emits Socket event → cleaner client notified.
5. Client → POST /payments/intent → Stripe service → Stripe API → webhook → Payment model → MongoDB.
6. Booking confirmed → Socket.io room created → messages persisted via Message model.
7. Client → PATCH /bookings/:id/complete → payment service → Stripe transfer → escrow released.
8. Both clients → POST /reviews → Review model → aggregate recalculated on User.

React client re-fetches profile via axios → updated ratings rendered.




5. Software Installation – Phase by Phase

P0 Setup
- Node.js LTS, npm.
- Git, GitHub account, repo init.
- VS Code + extensions (ESLint, Prettier, MongoDB, Tailwind).
- MongoDB Atlas account (or local MongoDB).
- Postman/Thunder Client.
- Client: `npm create vite@latest client -- --template react`; install `react-router-dom`, `axios`, Tailwind CSS, ESLint, Prettier. Optional state: `zustand` or Redux Toolkit.
- Server: `npm init`; install `express`, `mongoose`, `cors`, `dotenv`.
- Root: `.env`, `.gitignore`, optional `concurrently` for running both.

P1 Auth
- `bcrypt`, `jsonwebtoken`, `express-validator`, `cookie-parser`.

P2 Tasks/Bidding
- Mongoose models. No new installs.

P3 Scheduling
- Client: `react-big-calendar` (or similar). Utils: `date-fns` or `dayjs`.

P4 Payments
- Server: `stripe`. Client: `@stripe/stripe-js`. Stripe CLI.

P5 Ratings
- None.

P6 Chat
- `socket.io`, `socket.io-client`.

P7 Deploy
- Vercel (client), Render/Railway (server), MongoDB Atlas (DB), Cloudinary (images).
